# 08 – Notifications, Realtime & Push (MOBILE)

## Socket (`lib/socket.ts`, `useRealtime`)
Connect when authenticated + group present, `auth: {token}` (refresh on `connect_error` UNAUTHORIZED). **Lifecycle:** disconnect on app background (AppState) after 30s, reconnect on foreground and invalidate `['events']`, `['dashboard']`, `['notifications']`. Same event→cache handlers as web (`event:created/updated/deleted/completed`, `pin:changed`, `status:changed`, `notification:new`, `activity:new`, `group:*`). In-app toast (`react-native-toast-message`) for events from others; tap → open event. Suppress toast when push already shown (dedupe by `notificationId`).

## Notification center (More → Notifications, bell in headers)
FlatList newest first, tabs All/Unread, unread dot, icon by type, actor avatar, relative time, swipe or tap to mark read (optimistic), "Mark all as read" header action, infinite scroll, pull-to-refresh, empty state. Tap → navigate by `data.deepLink`. Tab bar / bell badge from `/notifications/unread-count` + realtime increments; also set app icon badge (`Notifications.setBadgeCountAsync`).

## Push notifications (critical)
- Use `expo-notifications` with **native device tokens** (`Notifications.getDevicePushTokenAsync()` → FCM token on Android, APNs token on iOS). Backend sends via Firebase Admin: for iOS, configure APNs key in Firebase console and use FCM iOS token (add `@react-native-firebase/messaging` OR the Expo config plugin route — **choose one and document it**; default: `expo-notifications` + FCM v1 via `googleServicesFile`; if iOS device token returned is APNs token, switch to `@react-native-firebase/messaging` to obtain the FCM token. Agent must verify end-to-end on a real device and record the chosen path in README).
- **Android:** create channel `syncmate-default` (importance HIGH, vibration, light colour primary) and `syncmate-reminders` before requesting permission; Android 13+ runtime permission `POST_NOTIFICATIONS`; notification small icon (monochrome) + accent colour.
- **iOS:** request permission contextually (after first event created or via a pre-permission explainer screen, never at first launch cold); handle provisional/denied states with "Open Settings" CTA (`Linking.openSettings()`).
- Registration: after login & permission granted → `POST /users/me/push-tokens {token, platform, deviceId}` (deviceId from `expo-application`/secure random persisted). Re-register on token refresh (`addPushTokenListener`) and on each app start (cheap upsert). Unregister on logout.
- Handlers: `setNotificationHandler` (show banner/sound when foregrounded only for types not already toasted), `addNotificationResponseReceivedListener` → parse `data.deepLink` → navigate (also handle cold-start via `getLastNotificationResponseAsync`).
- **Local fallback reminders (optional, offline resilience):** when the user sets reminders, additionally schedule local notifications (`scheduleNotificationAsync`) for the same times tagged with `eventId`+`reminderId`; cancel/reschedule when event changes/deleted/status registered (driven by realtime/refetch). Avoid double alerts: local ones use a distinct identifier and the server push dedupes via `notificationId` collapse key `collapse_key = eventId:reminderId` (document the expected backend `data.collapseKey`; if absent, prefer server push only and skip local scheduling – make this a feature flag `ENABLE_LOCAL_REMINDERS=false` by default).
- Settings screen toggles mirror backend (`pushNotifications`, `inAppNotifications`, `emailNotifications`, default reminders).
